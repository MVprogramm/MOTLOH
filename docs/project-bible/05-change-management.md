# 05 — История изменений и нерешённые вопросы

**Версия:** 1.0  
**Статус:** ACTIVE  
**Ответственность модуля:** определить порядок фиксации изменений, проектных решений и нерешённых вопросов.

---

## 1. Назначение

Этот модуль определяет, как в проекте фиксируются изменения, решения и нерешённые вопросы.

Его задача — сохранить историю проектных решений и исключить повторное обсуждение решений, уже принятых в проекте.

---

## 2. Изменение проекта

Изменением проекта считается любое утверждённое решение, которое влияет на:

- сценарий;
- структуру документов;
- методологию разработки;
- архитектуру проекта;
- производственный процесс.

Технические исправления, не изменяющие смысл, не считаются отдельным проектным изменением.

---

## 3. Источники истории

История проекта хранится в нескольких источниках. Каждый источник отвечает за свою область.

| Источник | Назначение |
|---|---|
| Git history | последовательность изменений файлов |
| BASELINE | утверждённое состояние материалов |
| REVIEW-документы | причины изменения конкретной сцены или материала |
| Open Questions | вопросы, ожидающие решения |

---

## 4. Нерешённые вопросы

Если решение отсутствует, вопрос фиксируется явно.

Каждый нерешённый вопрос должен содержать:

- описание проблемы;
- возможные варианты решения;
- текущий статус.

Допустимые статусы:

- `OPEN` — решение ещё не принято;
- `RESOLVED` — решение принято и внесено в проект;
- `DEFERRED` — рассмотрение отложено;
- `REJECTED` — предложенный вариант отклонён.

---

## 5. Закрытие вопроса

Вопрос считается закрытым только после принятия явного решения.

После принятия решения необходимо:

1. обновить соответствующий документ;
2. изменить статус вопроса;
3. сохранить изменение в Git.

Статус `RESOLVED` не используется, если решение существует только в чате и не внесено в основную ветку репозитория.

---

## 6. Отклонённые решения

Отклонённое предложение не удаляется, если его сохранение помогает понять историю выбора.

Ему присваивается статус `REJECTED`, а причина отклонения фиксируется кратко и однозначно.

Это предотвращает повторное обсуждение уже рассмотренного варианта без новых оснований.

---

## 7. Повторное рассмотрение

Закрытый или отклонённый вопрос может быть рассмотрен повторно.

Новое рассмотрение должно явно указывать:

- какое прежнее решение пересматривается;
- какие новые обстоятельства появились;
- почему прежнее решение больше не считается оптимальным.

Повторное рассмотрение не отменяет историю прежнего решения.

---

## 8. Критерий полноты истории

История проекта должна позволять ответить на три вопроса:

1. Что изменилось?
2. Почему это изменилось?
3. Когда изменение стало действующим?

Если хотя бы на один из этих вопросов невозможно ответить по документам проекта и Git history, история считается неполной.
