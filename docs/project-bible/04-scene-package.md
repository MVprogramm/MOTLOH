# Пакет сцены

Версия: 1.1

## Назначение

Каждая сцена разрабатывается как самостоятельный пакет рабочих документов.

Пакет разделяет подготовку, написание, проверку и канонический текст сценария.

Перед созданием пакета сцены соответствующая строка должна быть утверждена в [списке сцен](../story/scene-list.md).

## Расположение

Материалы разработки сцены хранятся в:

```text
docs/scenes/<scene-number>/
```

Текст сценария хранится отдельно в:

```text
script/<scene-number>-<short-name>.fountain
```

Каталог `script/` содержит только исходные файлы сценария.

## Стандартный пакет сцены

```text
docs/scenes/001/
├── README.md
├── 00-card.md
├── 01-purpose.md
├── 02-scenography.md
├── 03-references.md
├── 04-open-questions.md
└── 05-review.md
```

Используйте трёхзначные номера сцен, чтобы файлы всегда сохраняли правильный порядок.

## Назначение файлов

### `README.md`

Оглавление пакета сцены.

В нём фиксируются:

- номер сцены и рабочее название;
- текущий статус разработки;
- ссылки на все документы пакета;
- ссылка на соответствующий файл Fountain;
- статус BASELINE, если он присвоен.

### `00-card.md`

Краткая карточка сцены.

В ней фиксируются основные сведения, необходимые для идентификации сцены и определения её места в истории.

### `01-purpose.md`

Драматургическая конструкция сцены.

В документе определяются:

- функция сцены;
- непосредственная цель протагониста;
- противодействующая сила;
- конфликт;
- ставки;
- выбор;
- последствие;
- изменение между началом и концом сцены;
- связь с предыдущей и следующей сценами.

До начала написания сценарной сцены этот документ должен быть достаточно ясным.

### `02-scenography.md`

Визуальное и пространственное решение сцены, не зависящее от производственной среды.

Документ может включать:

- локацию и организацию пространства;
- мизансцену;
- входы, выходы, расположение и перемещения персонажей;
- композицию и визуальную иерархию;
- положение и движение камеры;
- свет, цвет, атмосферу и фактуру;
- декорации, реквизит, костюм и значимые предметы;
- визуальный ритм и переходы;
- ключевые образы и визуальные мотивы;
- источники звука, связанные с пространством;
- практические производственные ограничения.

Для анимации документ может дополнительно включать:

- ключевые позы;
- тайминг и спейсинг;
- постановку анимационного действия;
- применимые принципы анимации;
- правила трансформации и преувеличения.

Для игрового кино документ может дополнительно включать:

- движение актёров и физическое поведение;
- практические эффекты;
- выбор оптики и планов для монтажного покрытия;
- ограничения локации или декорации.

Документ описывает только те решения, которые служат драматургической задаче сцены.

### `03-references.md`

Референсы, используемые для решения конкретных задач сцены.

Для каждого референса необходимо указать:

- что именно используется как референс;
- какую задачу он помогает решить;
- что можно адаптировать;
- что нельзя копировать.

Референс без указанной функции добавлять не следует.

### `04-open-questions.md`

Нерешённые вопросы, которые могут повлиять на сцену.

Вопросы должны быть конкретными и предполагать практическое решение. Каждый вопрос получает один из статусов:

- открыт;
- решён;
- отложен;
- отклонён.

Принятые решения переносятся в соответствующий постоянный документ.

### `05-review.md`

Оценка написанной сцены.

В документе фиксируется:

- достигнута ли предполагаемая драматургическая функция;
- что изменилось во время написания;
- сильные стороны;
- слабые стороны;
- проблемы непрерывности;
- задачи для переработки;
- готовность к утверждению в качестве BASELINE.

Проверка должна оценивать фактически написанную сцену Fountain, а не только первоначальный замысел.

## Рабочий процесс

1. Утвердить соответствующую строку в [списке сцен](../story/scene-list.md).
2. Создать папку сцены на основе стандартного пакета.
3. Заполнить `00-card.md`.
4. Определить драматургическую конструкцию в `01-purpose.md`.
5. Разработать визуальное и пространственное решение в `02-scenography.md`.
6. Добавить в `03-references.md` только функциональные референсы.
7. Решить или явно отложить вопросы, блокирующие работу, в `04-open-questions.md`.
8. Написать сцену в соответствующем файле Fountain.
9. Оценить написанную сцену в `05-review.md`.
10. Выполнить локальную переработку.
11. Утверждать сцену как BASELINE только отдельным явным решением.

## Готовность к написанию

Сцена готова к написанию сценарного текста, когда:

- её драматургическая функция сформулирована явно;
- цель протагониста и противодействие определены;
- сцена приводит к значимому изменению;
- визуальная и пространственная логика осуществима;
- ни один нерешённый вопрос не блокирует действие;
- понятна предполагаемая связь с соседними сценами.

Подготовительные документы являются инструментами, а не заменой сценария. Их следует детализировать только в той мере, в какой это улучшает сцену.

## Обновление пакета

После написания сцены Fountain подготовительные документы нельзя незаметно переписывать так, чтобы первоначальный план выглядел правильным.

Если в процессе написания найдено лучшее решение:

1. зафиксировать отличие в `05-review.md`;
2. решить, следует ли сохранить новое решение;
3. явно обновить соответствующий подготовительный документ;
4. сохранить изменение в истории Git.

## Правило области действия

Информация, относящаяся к конкретной сцене, хранится в пакете этой сцены.

Общие правила проекта, темы, основы персонажей, структура и производственные стандарты хранятся в соответствующих документах проекта и не должны дублироваться в каждой папке сцены.

## Ограничение размера

Ни один файл не должен превышать 255 строк.

Если документ сцены становится слишком большим, его следует разделить по функциям, а не сжимать в плотный текст.
